# 毕设实验章节草稿：具身时序接球智能体的训练与分析

## 1. 实验目的

本章旨在系统评估所提出的具身时序接球智能体在 Unity 强化学习环境中的训练效果，并进一步分析该模型的内部表征、决策机制与分布外泛化能力。围绕这一目标，本章重点回答以下几个问题：

1. 所提出的模型能否在非特权输入条件下稳定学会接球任务。
2. 离线预热是否为后续强化学习提供了有效的表征先验。
3. 强化学习后的内部表示是否包含任务相关的空间认知与预测信息。
4. 模型在做动作决策时，究竟更依赖短时视觉、长时记忆还是自身状态。
5. 该模型在外观、尺度、动力学和像素分布发生变化时，是否具有一定泛化能力。

## 2. 实验设置

### 2.1 任务环境

实验环境为 Unity 中的小车接球任务。agent 需要在目标落地前将小车移动到落点附近，并利用车上的接球区域完成拦截。训练与评估行为名为 `CarCatch`。

环境的观测与动作设置如下：

- 输入仅包含视觉观测与车体自身平面速度。
- 不使用球的位置、速度等 privileged state 作为 policy 输入。
- 不使用车体绝对位置作为 policy 输入。
- 动作为二维连续控制，直接对应平面目标速度。

因此，该任务属于非特权输入下的具身闭环控制任务。

### 2.2 模型结构

本文采用的 agent 是在已有视觉时序模型基础上改造得到的具身控制模型，整体由三部分组成：

1. 短时视觉分支 `z_short`。  
   该分支以最近 `8` 帧图像为局部窗口，步长为 `4` 帧，用于提取当前的短时运动信息。

2. 自身状态分支 `z_self`。  
   该分支仅接收车体当前平面速度，并通过小型 MLP 编码为本体感觉表示。

3. 长时记忆分支 `h_long`。  
   将短时视觉与自身状态融合后送入 GRU，以维护跨时间的轨迹记忆与未来判断。

最终动作头同时读取：

- `z_short`
- `h_long`
- `z_self`

因此，模型并不是单纯依赖当前一帧视觉，也不是只依赖长时记忆，而是将即时感知、具身状态与时序记忆共同用于动作决策。

### 2.3 训练流程

本文采用两阶段训练范式：

1. 离线预热。  
   使用由启发式控制器自动生成的接球轨迹，对模型的时序表征进行监督预热，训练目标包括落点偏移和剩余时间等未来相关量。

2. 在线强化学习微调。  
   在 Unity + ML-Agents 环境中采用 PPO 对策略进行微调，使其从落点理解转向真实闭环控制。

这种“先学表示，再学控制”的流程，是本文实验设计中的关键部分。

## 3. 训练效果

### 3.1 离线预热结果

离线预热使用的数据集来自 `manual_capture/20260401_101517`，共包含 `1000` 条轨迹，其中训练/验证/测试划分为 `800/100/100`。

在 warmup 阶段，模型并不是直接学习动作策略，而是学习两个未来相关的监督目标：

1. 落点偏移 `landing_offset`
2. 剩余落地时间 `time_to_land`

对应地，损失函数由两部分组成：

1. 落点损失 `landing_loss`  
   对二维落点偏移使用逐维均方误差。具体做法是先对 `x/z` 两个分量求平方误差，再在最后一个维度上取平均，得到每个时间步的 `landing_mse`。

2. 时间损失 `time_loss`  
   对剩余落地时间使用 `Smooth L1 Loss`，而不是普通 L2。这样既能保持误差较小时的稳定优化，又能避免个别较大时间误差在训练初期主导梯度。

总损失写为：

`L = L_landing + lambda_t * L_time`

其中 `lambda_t` 为时间损失权重。训练实现中，这两个损失都会进一步乘以 `valid_mask` 做 masked mean，只在有效时间步上累计，从而避免补齐窗口或无效位置对优化目标造成干扰。

预热结果表明，模型已经能够较准确地从视觉时序中恢复未来相关量。验证集与测试集的主要指标如下：

- best validation loss: `0.3834`
- test loss: `0.3103`
- validation landing L2: `0.5065`
- test landing L2: `0.4756`
- validation time MAE: `0.0502`
- test time MAE: `0.0518`

这说明在进入强化学习之前，模型已经具备了较强的未来轨迹理解能力。

### 3.2 在线强化学习结果

在线训练采用 PPO，主要超参数包括：

- `batch_size = 512`
- `buffer_size = 20480`
- `learning_rate = 3e-4`
- `memory.sequence_length = 16`
- `memory_size = 64`
- `max_steps = 500000`

训练结果表明，该 agent 能够在原始环境中稳定学会接球任务。正式 run `temp_realTime_0001` 的表现如下：

- `50000` step 时，`SuccessRate ≈ 0.262`
- `355000` step 时，`SuccessRate = 1.000`
- `360000` step 时，`SuccessRate = 1.000`

在后期阶段，累计回报稳定在约 `71` 左右，说明模型已经收敛到稳定的高水平接球策略。

### 3.3 定性观察

在 Unity Editor 中进行 Python inference 观察时，可以看到：

- 小车能够稳定判断球的落点趋势。
- 行为较为平滑，不是随机抖动式试探。
- 整体上呈现出“先观察、再移动并持续修正”的特征。

这说明该模型不仅在数值指标上达到了高成功率，也在行为层面表现出明显的闭环控制特性。

## 4. 表征分析：RL 后模型是否学到了空间认知

为了研究模型内部是否形成了任务相关的空间表征，本文对强化学习后的最终策略进行了线性 probe 分析。

### 4.1 Probe 方法

在不改变模型输入的前提下，分别提取以下内部表示：

- `short`
- `self`
- `memory`
- `long`
- `readout`

这些表征并不是随意命名的中间向量，而是与模型中的具体层一一对应：

1. `short`  
   对应短时视觉分支的输出，即 `encode_local_windows()` 之后再经过 `token_proj` 得到的 `short_token`。它位于局部视觉 backbone 与长时记忆之间，代表当前局部窗口的短时运动表征。

2. `self`  
   对应自身状态分支的输出，即 `encode_self_state()` 之后的 `self_token`。它由 `self_state_encoder` 产生，主要编码车体当前平面速度。

3. `memory`  
   对应送入 GRU 之前的记忆输入，即 `fuse_memory_input(short_token, self_token)` 得到的 `memory_token`。这一层表示短时视觉与自身状态已经完成第一次融合，但尚未被长时记忆递归整合。

4. `long`  
   对应长时记忆分支的输出，即 `long_gru` 的当前输出 `long_feat`。它代表模型在当前时刻对整段观测历史的压缩状态。

5. `readout`  
   对应动作头与价值头真正读取的最终融合向量，即 `build_readout_input(short_token, long_feat, self_token)` 的输出。它是 `[short, long, self]` 三者拼接后的读出输入，也是 `policy_head`、`value_head`、`landing_head` 与 `time_head` 共同使用的高层表示。

然后用线性回归测试这些表示中能否解码出以下目标：

- `landing_offset`
- `ball_rel_pos`
- `ball_rel_vel`
- `self_velocity`
- `time_to_land`

如果某一层表示能够较好地被线性解码出这些量，则说明该层已经显式或近显式地编码了对应的空间与时序信息。

### 4.2 RL 后模型的 probe 结果

强化学习后模型的测试集 `R^2` 如下：

| feature | landing_offset | ball_rel_pos | ball_rel_vel | self_velocity | time_to_land |
|---|---:|---:|---:|---:|---:|
| short | 0.6154 | 0.9964 | 0.5644 | 0.6406 | 0.9806 |
| self | 0.1833 | 0.6190 | 0.4658 | 1.0000 | 0.6295 |
| memory | 0.7093 | 0.9905 | 0.7953 | 0.9777 | 0.9793 |
| long | 0.6879 | 0.9831 | 0.7900 | 0.9282 | 0.9763 |
| readout | 0.7753 | 0.9975 | 0.8650 | 1.0000 | 0.9880 |

### 4.3 结果解释

上述结果表明：

1. `short` 强烈编码了球相对车的当前位置与剩余落地时间，因此更像当前空间知觉。
2. `self` 几乎完美编码自身速度，说明该分支确实主要承担本体感觉功能。
3. `memory` 与 `long` 对 `landing_offset` 和 `ball_rel_vel` 的解码能力更强，说明长时分支更偏向未来轨迹判断与预测性记忆。
4. `readout` 在多数指标上最强，说明动作头前的融合表示已经把当前视觉、长时记忆与自身状态整合在了一起。

因此，可以较为谨慎地认为，强化学习后的模型已经学到了以自身为中心的、面向行动的预测性空间表征，而不只是简单动作拟合。

## 5. Warmup 与 RL 后模型的对照

为了进一步判断强化学习阶段究竟是“重新学会了空间认知”，还是“继承并重组了 warmup 的表征先验”，本文对 warmup checkpoint 与 RL 后 checkpoint 做了相同的 full probe 对照。

### 5.1 对比结果

关键 `R^2` 对比如下：

| feature | target | warmup | RL后 |
|---|---|---:|---:|
| short | landing_offset | 0.7420 | 0.6154 |
| short | ball_rel_pos | 0.9976 | 0.9964 |
| short | ball_rel_vel | 0.6116 | 0.5644 |
| short | time_to_land | 0.9867 | 0.9806 |
| memory | landing_offset | 0.8183 | 0.7093 |
| memory | ball_rel_vel | 0.8419 | 0.7953 |
| long | landing_offset | 0.8987 | 0.6879 |
| long | ball_rel_vel | 0.8705 | 0.7900 |
| readout | landing_offset | 0.9014 | 0.7753 |
| readout | ball_rel_pos | 0.9985 | 0.9975 |
| readout | ball_rel_vel | 0.9087 | 0.8650 |
| readout | time_to_land | 0.9929 | 0.9880 |

### 5.2 结果解释

一个非常清楚的趋势是：warmup 在几乎所有 probe 指标上都强于 RL 后模型，尤其在 `landing_offset` 和 `ball_rel_vel` 上差异更明显。

这一现象说明：

- warmup 阶段学到的是更显式的预测性表征。
- RL 阶段并没有把这些表征学没，而是将它们压缩并重组为更适合动作控制的内部状态。

换言之，强化学习不是从零学会空间认知，而是在已有表征先验的基础上进行任务适配。这一点对本文的训练方法具有重要支持作用。

## 6. 因果遮挡分析：模型到底依赖谁来做动作

仅通过 probe 还不足以回答“模型到底有没有在用这些信息”。因此，本文进一步在真实 build 环境中进行了因果遮挡实验。

### 6.1 实验方法

在冻结策略评估条件下，仅对动作读出端做干预，而不破坏记忆更新本身。具体设置如下：

- `short_readout = 0`：动作头看不到 `short`，但 `short` 仍进入 `GRU`
- `long_readout = 0`：动作头看不到 `long`，但 `long` 仍正常更新
- `self_readout = 0`：动作头看不到 `self`，但 `self` 仍参与记忆更新

每组评估使用：

- `4` 个并行环境
- `5000` step
- 原始完整模型初始化
- 不进行参数更新

### 6.2 结果

| condition | SuccessRate | Cumulative Reward | Episode Length |
|---|---:|---:|---:|
| baseline | 1.000 | 71.34 | 32.4 |
| short_readout = 0 | 0.533 | 5.88 | 33.6 |
| long_readout = 0 | 0.667 | 38.95 | 32.8 |
| self_readout = 0 | 1.000 | 70.86 | 33.2 |

### 6.3 结果解释

该实验给出了比 probe 更强的因果证据：

1. `short -> action head` 是最关键的读出通路。  
   即使 `short` 仍然能够进入长时记忆，只要动作头看不到 `short`，成功率仍会从 `1.0` 下降到约 `0.53`。

2. `long -> action head` 同样重要，但次于 `short`。  
   当动作头看不到 `long` 时，成功率下降到约 `0.67`，说明长时记忆确实在支持动作决策。

3. `self -> action head` 在当前环境中的直接贡献较小。  
   将其从读出中去掉后，成功率仍保持在 `1.0`，说明当前任务中真正决定成败的主要是短时视觉和长时记忆。

综上，当前 agent 的接球机制可以概括为：

- 以最新短时视觉为主导
- 以长时记忆为重要补充
- 以自身状态为轻量辅助

## 7. 泛化实验

为了评估该 agent 在分布外环境中的鲁棒性，本文在多个修改后的 Unity build 上进行了冻结策略评估。

### 7.1 实验设置

泛化实验保持以下条件不变：

- 使用原始训练好的完整模型
- 不使用任何遮挡
- `4` 个并行环境
- 每组 `5000` step
- 不进行参数更新

测试环境包括：

- 原环境 `e2_360_0_6`
- 抛射圆柱体 `cylinder`
- 抛射方块 `cube`
- 更小目标 `smallBall`
- 更大重力加速度 `fastg`
- 原环境 + 灰度反转输入

其中，`smallBall` 采用的是重新 build 后的重跑结果，旧结果因目录混淆而作废。

### 7.2 结果

| environment | SuccessRate | Cumulative Reward | Episode Length |
|---|---:|---:|---:|
| baseline | 1.000 | 71.34 | 32.40 |
| cylinder | 0.500 | 17.08 | 34.07 |
| cube | 0.800 | 50.35 | 33.64 |
| smallBall | 0.533 | -1.18 | 33.87 |
| fastg | 0.947 | 64.87 | 23.89 |
| grayscale invert | 0.000 | -113.71 | 23.10 |

### 7.3 结果分析

泛化实验呈现出明显的“选择性鲁棒性”：

1. 对动力学偏移具有较强鲁棒性。  
   在 `fastg` 环境中，尽管目标下落更快，成功率仍然达到约 `0.95`。这说明模型并不只是记住原环境中的固定时间尺度，而是确实掌握了一部分轨迹层面的规律。

2. 对形状变化具有中等鲁棒性。  
   `cube` 的表现尚可，成功率约 `0.80`；而 `cylinder` 降至约 `0.50`，说明模型能一定程度上适应目标外观变化，但对具体轮廓与视觉运动模式仍然敏感。

3. 对目标尺度缩小较为敏感。  
   `smallBall` 的成功率下降到约 `0.53`，说明模型对目标视觉显著性的降低并不鲁棒。

4. 对低层亮度分布变化几乎完全不具备鲁棒性。  
   灰度反转后成功率直接下降到 `0`，表明当前视觉编码器明显依赖训练分布中的亮度统计和对比度结构。

综合来看，当前模型的泛化能力更偏向动力学与轨迹层面的迁移，而不是完全外观无关的稳健表示。

## 8. 本章小结

通过以上实验，可以得到如下结论：

1. 所提出的具身时序控制模型能够在非特权输入条件下稳定学会 Unity 接球任务。
2. 离线预热为后续强化学习提供了强有力的未来表征先验。
3. 强化学习后的内部状态中仍保留着显著的空间位置、相对速度与剩余时间信息，说明模型已形成任务相关的预测性空间表征。
4. 因果遮挡表明，动作决策最依赖短时视觉直连，其次依赖长时记忆，自身状态在当前任务中更多是辅助信息。
5. 泛化实验表明，该模型对动力学偏移具有较强鲁棒性，但对目标尺寸变化与低层亮度分布变化较为敏感。

因此，本文提出的模型不仅在训练环境中取得了高成功率，也为“具身时序表征如何支持强化学习控制”提供了较完整的实验性证据。
